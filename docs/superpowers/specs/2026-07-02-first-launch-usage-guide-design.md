# 首次安装使用与配置引导页设计

## 背景

当前首次安装引导已经包含 3 页产品核心能力预览：

- 数据归家
- 数字分身
- 自动执行

这 3 页适合解释“为什么使用这个 App”，但用户完成预览后仍缺少一页简单说明，告诉他们每类能力应该从哪里开始使用，以及关键配置入口在哪里。新用户进入首页后如果不知道“汇总”“聊天/任务”“设置中心”各自承担什么职责，可能会在首次体验中断。

本设计在现有首次安装引导后追加一页“使用与配置清单”，用轻量方式补齐“怎么开始用”的认知，不把首次启动做成完整配置向导。

## 目标

- 在现有 3 页产品预览后追加第 4 页“开始使用”。
- 第 4 页介绍三类核心能力的使用入口和配置入口。
- 保持首次启动体验轻量，不读取配置、不请求权限、不跳转到设置子页。
- 完成后仍进入首页，并写入首次引导完成状态。
- 保持底部 Tab 在引导期间隐藏，完成后恢复现有首页与 Tab。
- 不改变首页、设置页、任务页、聊天页和模型配置的业务行为。

## 非目标

- 不在引导页里检测 API Key、模型文件、HDC 或权限状态。
- 不在引导页里直接写入配置或启动下载。
- 不把第 4 页做成可点击跳转卡片。
- 不增加显眼“跳过”入口。
- 不新增独立路由，不把引导页放入 router 栈。
- 不替换已有 3 张产品预览图。

## 已确认方案

采用“3 页产品预览 + 1 页使用清单”的结构。

前 3 页保持当前价值表达和视觉资产：

1. 数据归家
2. 数字分身
3. 自动执行

第 4 页标题为“开始使用”，内容由三张清单卡组成：

1. 数据归家：说明去“汇总”查看采集和整理结果，去“设置 > 数据采集”配置图库、OCR、Embedding、地图服务。
2. 数字分身：说明在“首页”生成或更新数字分身，去“设置 > 个人与隐私”配置图片服务与确认策略。
3. 自动执行：说明去“聊天/任务”发起目标，去“设置 > 模型与智能体 / 任务与自动化”配置 Planner、Decider、HDC 和 Workflow。

第 4 页只负责说明，不承载实际配置动作。这样能让用户形成路径记忆，同时避免首次启动阶段因为权限、网络、模型服务或密钥状态而变重。

## 页面结构

沿用现有 onboarding 模块边界：

- `entry/src/main/ets/pages/onboarding/FirstLaunchOnboarding.ets`
- `entry/src/main/ets/pages/onboarding/OnboardingTypes.ets`

`OnboardingTypes.ets` 继续负责稳定数据和纯函数：

- onboarding 版本常量
- 持久化 key
- slide 数据
- 最后一页判断
- 按钮文案
- index clamp

`FirstLaunchOnboarding.ets` 继续只负责渲染和 `onComplete()` 回调：

- 第 1-3 页渲染产品预览图和说明。
- 第 4 页渲染使用清单卡片。
- 前 3 页按钮为“下一页”。
- 第 4 页按钮为“进入首页”。
- 点击“进入首页”后调用 `onComplete()`。

`Index.ets` 不新增复杂状态，只继续执行当前逻辑：

- 判断是否展示首次引导。
- 引导完成后切回 `MainTabIndex.Home`。
- 写入完成版本。

## 持久化与版本

当前持久化 key 保持不变：

```text
firstLaunchOnboardingVersion
```

本次更新首次引导版本值为：

```text
2026-07-core-preview-usage-guide
```

原因是第 4 页属于首次引导内容变化。版本化后，清空安装或新安装用户一定看到新 4 页；已完成旧 3 页的开发/测试设备也能在版本升级后重新看到一次新版引导，便于验证。完成新版引导后再次启动不再出现。

如果发布策略希望老用户不再看到新版引导，可以保持旧版本值不变；但本次需求明确是“首次启动时增加”，设计默认采用 bump version，保证新增页面能被实际展示和测试。

## 交互规则

- 第 1-3 页可继续左右滑动，也可点击“下一页”。
- 第 4 页是最后一页，主按钮为“进入首页”。
- 不新增显眼跳过入口。
- 第 4 页清单卡不做点击跳转，避免用户在首次引导里进入复杂配置流。
- 引导期间不显示底部 Tab。
- 用户关闭 App 或系统返回时不写完成状态，下次启动继续展示。

## 第 4 页内容

### 标题

开始使用

### 说明

三步建立你的个人智能助手：先汇总数据，再生成数字分身，最后让 Agent 执行任务。

### 清单卡 1：数据归家

- 使用入口：汇总
- 配置入口：设置 > 数据采集
- 文案：同步聊天、图库和位置线索，在汇总页查看整理后的个人事件。

### 清单卡 2：数字分身

- 使用入口：首页
- 配置入口：设置 > 个人与隐私
- 文案：基于个人画像和头像生成数字分身，用于问答、朗读和长期陪伴。

### 清单卡 3：自动执行

- 使用入口：聊天 / 任务
- 配置入口：设置 > 模型与智能体、任务与自动化
- 文案：配置 Planner、Decider 和 HDC 后，让 Agent 按目标规划并执行任务。

## 视觉设计

第 4 页不再新增生成图，避免为说明性页面继续扩大资源体积。

使用 ArkUI 原生布局：

- 浅色背景与现有 onboarding 一致。
- 三张白色圆角卡片纵向排列。
- 每张卡使用小图标字母或色块标识功能类别。
- 强调色沿用现有三页：
  - 数据归家：蓝色
  - 数字分身：紫色
  - 自动执行：绿色
- 文本字号与现有 onboarding 保持一致，保证 1080 x 2340 手机预览下不溢出。

## 风险与规避

- 风险：第 4 页信息过多导致用户阅读负担增加。
  - 规避：每张卡只保留“使用入口、配置入口、一句话说明”，不展开配置详情。
- 风险：version bump 会让已完成旧引导的设备再次看到新版引导。
  - 规避：这是版本化引导的预期行为；若发布时不希望老用户看到，可保留旧版本值。
- 风险：如果第 4 页做成可跳转入口，可能引入 Tab 状态、设置子页滚动和返回行为复杂度。
  - 规避：本次明确不跳转，只做说明。
- 风险：`FirstLaunchOnboarding.ets` 中进度点若继续写死 3 个，会遗漏第 4 页。
  - 规避：实现时应将进度点改为遍历 slide 数组，避免页数变化导致 UI 不一致。

## 验收标准

- 首次引导总页数为 4 页。
- 第 4 页清晰说明三类核心能力的使用入口和配置入口。
- 第 4 页不读配置、不发网络请求、不触发权限、不跳转。
- 点击“进入首页”后进入首页并写入完成状态。
- 完成后再次启动不再展示引导页。
- 现有首页、汇总、聊天、任务、设置页面行为不变。
